## 一、OTA 更新速度优化（高优先级）

### 问题描述

当前 OTA 固件升级（约 400KB）耗时过长，实际测试大约为3分半，主要瓶颈在发送端固定延时和 W25Q32 逐字节传输。

### 1.1 发送端固定延时（最大瓶颈）

**文件：** `OTA/app_update_send/Drivers/bootloader/App_update.c`

```c
// 每发送 256 字节，固定延时 100ms
if (update_data_len % 256 == 0)
{
    HAL_Delay(100);
}
```

**影响：**
- 400KB 固件 = 1600 个 256 字节块
- 1600 × 100ms = **160 秒纯延时**
- 这是整个 OTA 流程最大的时间浪费

**优化方案：改为 ACK 应答机制**

```c
// 发送端：等待接收端确认后再发下一块
if (update_data_len % 256 == 0)
{
    // 发送完一块，等待 ACK
    wait_for_ack();
}

// 接收端：写入 Flash 后发送 ACK
void page_write_done(void)
{
    uint8_t ack = 0xAA;
    CAN_SendMsg(ACK_ID, &ack, 1);
}
```

**预期效果：** 消除 160 秒固定延时，OTA 总时间缩短 3-5 倍。

---

### 1.2 W25Q32 逐字节 SPI 传输

**文件：** `Vehicle_screen_controller/Drivers/bootloader/Int_w25q32.c`

```c
// 当前：逐字节写入，每次调用 HAL 函数
for (uint16_t i = 0; i < len; i++)
{
    Int_w25q32_write_byte(data[i]);  // 每字节一次 HAL_SPI_Transmit 调用
}
```

**问题：**
- 256 字节 = 256 次 `HAL_SPI_Transmit()` 调用
- 每次调用有函数开销、参数检查、标志轮询
- SPI 时钟 9MHz，理论传输 256 字节只需 0.23ms
- 实际因 HAL 开销可能需要 1-2ms

**优化方案：批量 SPI 传输**

```c
// 优化后：一次传输整页数据
HAL_SPI_Transmit(&hspi2, data, len, 100);  // 一次 HAL 调用
```

**预期效果：** W25Q32 写入速度提升 2-3 倍。

---

### 1.3 W25Q32 擦除策略

**文件：** `Vehicle_screen_controller/Drivers/bootloader/storage.c`

```c
// 当前：逐扇区擦除（4KB/扇区）
for (int i = 0; i < 128; i++)
{
    Int_w25q32_erase_sector(i);  // 每扇区 45-400ms
}
```

**问题：**
- 128 扇区 × 平均 200ms = **25.6 秒**
- 实际固件可能不需要擦除全部 128 扇区

**优化方案：使用块擦除 + 按需擦除**

```c
// 方案1：使用 64KB 块擦除（替代 16 个 4KB 扇区擦除）
Int_w25q32_erase_block_64k(block_num);  // 64KB 块擦除 ~150ms

// 方案2：根据固件大小计算实际需要的扇区数
uint32_t sectors_needed = (firmware_size + 4095) / 4096;
for (int i = 0; i < sectors_needed; i++)
{
    Int_w25q32_erase_sector(i);
}
```

**预期效果：** 擦除时间从 25 秒降至 5-10 秒。

### 1.4 Bootloader Flash 拷贝优化

**文件：** `OTA/bootloader_start/bootloader/app_bootloader.c`

```c
// 当前：逐半字写入内部 Flash
for (uint16_t i = 0; i < FLASH_PAGE_SIZE; i += 2)
{
    data_tmp = flash_data_buff[i] | flash_data_buff[i + 1] << 8;
    HAL_FLASH_Program(FLASH_TYPEPROGRAM_HALFWORD, APP_START + offset + i, data_tmp);
}
```

**问题：**
- 2KB 页 = 1024 次 `HAL_FLASH_Program()` 调用
- 每次半字写入约 40us
- 2KB 写入耗时：1024 × 40us = **40.96ms**
- 400KB 固件 = 200 页 × 40.96ms = **8.19 秒**

**优化方案：使用 32 位字写入**

```c
// 优化后：使用 32 位字写入，调用次数减半
for (uint16_t i = 0; i < FLASH_PAGE_SIZE; i += 4)
{
    data_tmp = flash_data_buff[i] | (flash_data_buff[i+1] << 8) |
               (flash_data_buff[i+2] << 16) | (flash_data_buff[i+3] << 24);
    HAL_FLASH_Program(FLASH_TYPEPROGRAM_WORD, APP_START + offset + i, data_tmp);
}
```

**预期效果：** Flash 写入时间从 8 秒降至 4 秒。

### 1.5 Bootloader W25Q32 读取优化

**文件：** `OTA/bootloader_start/bootloader/Int_w25q32.c`

```c
// 当前：逐字节读取

```

**优化方案：批量读取**

```c

```

## 二、LCD/LVGL 显示性能优化（中优先级）

### 问题描述

LCD 刷新率偏低，理论最高约 10fps，实际可能更低。

### 2.1 LVGL 绘图缓冲区过小

**文件：** `Vehicle_screen_controller/lvgl/porting/lv_port_lcd_stm32.c`

```c
// 当前：单缓冲，16 行
static lv_color_t buf1[MY_DISP_HOR_RES * 16];  // 240 × 16 × 2 = 7,680 字节
```

**问题：**
- 屏幕 240×320，每次刷新 16 行
- 完整一帧需要 320/16 = 20 次 flush
- 每次 flush 后等待 5ms（任务延时）
- 理论最高帧率：1000ms / (20 × 5ms) = **10fps**

**优化方案：增大缓冲区**

```c
// 优化后：40 行缓冲
static lv_color_t buf1[MY_DISP_HOR_RES * 40];  // 240 × 40 × 2 = 19,200 字节
```

**预期效果：** flush 次数从 20 降至 8，帧率提升至 25fps+。

---

### 2.2 禁用未使用的颜色格式

**文件：** `Vehicle_screen_controller/lvgl/lv_conf.h`

```c
// 当前：启用所有颜色格式（浪费 Flash）
#define LV_DRAW_SW_SUPPORT_RGB565       1
#define LV_DRAW_SW_SUPPORT_RGB888       1  // 未使用
```

**优化方案：仅保留 RGB565**

```c
#define LV_DRAW_SW_SUPPORT_I1           0
```

**预期效果：** 节省约 10-20KB Flash。

## 三、CAN 通信效率优化（中优先级）

### 3.1 ISR 三重队列拷贝

**文件：** `Vehicle_screen_controller/Core/Src/can.c`

```c
// 当前：每条 CAN 消息拷贝到 3 个队列
xQueueSendFromISR(can_rx_queue, &msg, &xHigherPriorityTaskWoken);
xQueueSendFromISR(mqtt_can_rx_queue, &msg, &xHigherPriorityTaskWoken);
xQueueSendFromISR(lvgl_can_rx_queue, &msg, &xHigherPriorityTaskWoken);
```

**问题：**
- 每条消息 3 次 memcpy（每次约 12-16 字节）
- 同一消息被 3 个任务独立处理，浪费 CPU

**优化方案：单队列 + 发布订阅**

```c
// 优化后：单队列，根据消息类型分发
xQueueSendFromISR(can_rx_queue, &msg, &xHigherPriorityTaskWoken);
// 各任务从同一队列读取，根据 CAN ID 决定是否处理
```

---

### 3.2 CAN 发送超时实现

**文件：** `Vehicle_screen_controller/Core/Src/can.c`

```c
// 当前：CPU 循环计数（不是真正的时间超时）
int timeout = 100000;  // 注释写的 "unit ms"，实际是 CPU 周期
while (__HAL_CAN_GET_FLAG(&hcan, CAN_FLAG_TXOK0) == 0 && timeout--) {}
```

**问题：**
- 100000 次循环 ≈ 1.4ms（72MHz），不是 100ms
- 只检查 TXOK0，忽略 mailbox 1/2

**优化方案：使用 HAL_GetTick()**

```c
uint32_t start = HAL_GetTick();
while (HAL_GetTick() - start < 100)  // 真正的 100ms 超时
{
    if (__HAL_CAN_GET_FLAG(&hcan, CAN_FLAG_TXOK0) ||
        __HAL_CAN_GET_FLAG(&hcan, CAN_FLAG_TXOK1) ||
        __HAL_CAN_GET_FLAG(&hcan, CAN_FLAG_TXOK2))
        break;
}
```

---

### 3.3 自动重传已禁用

**文件：** `Vehicle_screen_controller/Core/Src/can.c`

```c
hcan.Init.AutoRetransmission = DISABLE;
```

**问题：** CAN 帧碰撞后丢失，控制命令可能不可靠。

**优化方案：启用自动重传**

```c
hcan.Init.AutoRetransmission = ENABLE;
```

## 四、FreeRTOS 任务配置优化（低优先级）

### 4.1 AT_Parse 任务栈过小

**文件：** `Vehicle_screen_controller/Core/Src/freertos.c`

```c
// 当前：68 words = 272 字节（危险）
xTaskCreate(AT_Parse, "AT_parse", 68, NULL, 15, &AT_pars_handle);
```

**问题：** AT 命令解析可能使用局部缓冲区，272 字节容易溢出。

**优化方案：增加栈大小**

```c
xTaskCreate(AT_Parse, "AT_parse", 128, NULL, 15, &AT_pars_handle);  // 512 字节
```

---

### 4.2 内存使用紧张

**当前 RAM 使用估算：**

| 组件 | 大小 | 说明 |
|------|------|------|
| FreeRTOS 堆 | 25,000 | `configTOTAL_HEAP_SIZE` |
| LVGL 内部堆 | 19,456 | `LV_MEM_SIZE` |
| LVGL 绘图缓冲 | 7,680 | 240 × 16 × 2 |
| 全局变量 | ~2,000 | CAN/UART 缓冲区 |
| 主栈 + ISR | ~1,500 | |
| **总计** | **~56KB** | 64KB RAM 中仅剩 ~8KB |

**优化方案：**
- 减小 `LV_MEM_SIZE` 至 14KB（如 UI 简单）
- 使用 `uxTaskGetStackHighWaterMark()` 监控实际栈使用
- 禁用 `configUSE_STATS_FORMATTING_FUNCTIONS`

## 五、可靠性问题（高优先级）

### 5.1 Bootloader W25Q32 忙等待无超时

**文件：** `OTA/bootloader_start/bootloader/Int_w25q32.c`

```c
// 当前：无超时保护，可能死循环
static void Int_w25q32_wait_busy(void)
{
    while (1)
    {
        Int_w25q32_write_byte(W25Q32_READ_STATUS_REG);
        uint8_t status = Int_w25q32_read_byte();
        if ((status & 0x01) == 0)
            break;
    }
}
```

**优化方案：添加超时**

```c
static void Int_w25q32_wait_busy(void)
{
    uint32_t start = HAL_GetTick();
    while (1)
    {
        Int_w25q32_write_byte(W25Q32_READ_STATUS_REG);
        uint8_t status = Int_w25q32_read_byte();
        if ((status & 0x01) == 0)
            break;
        if (HAL_GetTick() - start > 5000)  // 5 秒超时
        {
            printf("W25Q32 timeout!\r\n");
            break;
        }
    }
}
```
