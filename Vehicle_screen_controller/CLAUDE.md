# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## 1. System Overview

**Vehicle Screen Controller** — an STM32F103ZE-based car dashboard integrating LVGL GUI, FreeRTOS real-time scheduling, CAN bus vehicle networking, MQTT IoT cloud connectivity, voice recognition, and OTA firmware updates.

### Architecture Layers

```
+-------------------------------------------------------------+
|                    Application Layer                         |
|  freertos.c: oled_task | voice_task | lvgl_demo | can_task  |
|  lvgl/ui/ui.c: custom UI screens and widgets               |
+-------------------------------------------------------------+
|                    Middleware Layer                           |
|  FreeRTOS v10.3.1 (CMSIS-RTOS V2) | LVGL v9.5.0-dev        |
|  mqttclient (MQTT v3.1.1) | OTA state machine               |
+-------------------------------------------------------------+
|                    Driver Layer                              |
|  ATK-MD0280 (LCD+Touch) | SSD1306 (OLED) | CAN driver       |
|  ESP8266 AT commands | W25Q128 (SPI Flash) | AT24C02 (EEPROM)|
+-------------------------------------------------------------+
|                    Hardware Layer                            |
|  STM32F103ZE (Cortex-M3, 72MHz, 64KB SRAM, 512KB Flash)     |
|  ILI9341 LCD | XPT2046 Touch | CAN Transceiver | ESP8266    |
+-------------------------------------------------------------+
```

### Tech Stack

|-----------|-----------|----------------|

## 2. Build System

This project uses **Keil MDK-ARM** with ARMCC V5.06 compiler.

To build:
1. Open `MDK-ARM/CAR.uvprojx` in Keil uVision
2. Build using Project -> Build Target (F7)

Output files:
- `MDK-ARM/CAR/CAR.axf` — ELF binary
- `MDK-ARM/CAR/CAR.hex` — Intel HEX for flashing
- `MDK-ARM/CAR/CAR.map` — Linker map (check for memory overflow)
- `MDK-ARM/CAR/CAR.sct` — Scatter/linker script

The initial project skeleton was generated by **STM32CubeMX** (`CAR.ioc` file present). CubeMX-generated code is in `Core/Src/` and `Core/Inc/`; user-written drivers are in `Drivers/hardware/`.

## 4. Memory Architecture

### SRAM Budget (64KB total)

| Component | Size | Config Location | Notes |
|-----------|------|----------------|-------|
| FreeRTOS heap | 32KB | `configTOTAL_HEAP_SIZE` in `FreeRTOSConfig.h` | Heap scheme 4 (coalescing first-fit) |
| LVGL heap | 12KB | `LV_MEM_SIZE` in `lv_conf.h` | Builtin allocator, no expansion |
| LVGL display buffer | 7.68KB | `lv_port_lcd_stm32.c` (static array) | 240 x 16 pixels x 2 bytes, single buffer |
| LVGL draw layer buffer | up to 8KB | `LV_DRAW_LAYER_SIMPLE_BUF_SIZE` | Allocated from LVGL heap on demand |
| FreeRTOS task stacks | ~7.68KB | See task table below | Sum of all active task stacks |
| Global variables (.data/.bss) | ~2-3KB | Linker-managed | Queues, CAN structs, OLED framebuffer, etc. |
| **Estimated total** | **~60-62KB** | | **Very tight — monitor via `CAR.map`** |

> **WARNING**: The actual FreeRTOS heap is **32KB** (not 15KB as previously documented). Combined with LVGL's 12KB heap and 7.68KB display buffer, this leaves very little margin. Always check `CAR.map` after building.

### Flash Memory Layout

| Region | Address | Size | Content |
|--------|---------|------|---------|
| Bootloader | `0x08000000` | 64KB | OTA bootloader (jumps to app) |
| Application | `0x08010000` | 448KB | Main firmware (this project) |

The OTA module writes an 8-byte header (app start address + size) to W25Q128, then sets update flags in AT24C02 EEPROM before jumping to the bootloader.

## 5. Driver Layer

### LCD Driver (ATK-MD0280)

- **Location**: `Drivers/hardware/LCD_touch_ATK_MD0280/`
- **Controller**: ILI9341, 240x320, RGB565
- **Interface**: FSMC Bank 4, 16-bit parallel
- **Files**: `atk_md0280.c`, `atk_md0280_fsmc.c` (LCD), `atk_md0280_touch.c`, `atk_md0280_touch_spi.c` (touch)
- **LVGL porting**: `lvgl/porting/lv_port_lcd_stm32.c` — flush callback sends pixels via ILI9341 command sequence (0x2A column set, 0x2B page set, 0x2C memory write)

### OLED Driver (SSD1306)

- **Location**: `Drivers/hardware/OLED.c`, `OLED.h`, `OLED_Data.c`, `OLED_Data.h`
- **Resolution**: 128x64, organized as 8 pages x 128 columns
- **Interface**: Software I2C bit-banging on PB10 (SCL) / PB11 (SDA)
- **Framebuffer**: `OLED_DisplayBuf[8][128]` — full screen buffer in RAM
- **Font support**: ASCII + GB2312 Chinese (16x16 dot-matrix)
- **API**: Character/string display, numeric display, printf, geometric primitives (line, rectangle, circle, ellipse, arc), partial area update

### CAN Driver

There are **two separate CAN implementations**:

**A. Application CAN** (`Core/Src/can.c`, `Core/Inc/can.h`):
- Used by the main FreeRTOS application
- 500 kbps (prescaler=36, BS1=2TQ, BS2=3TQ at 36MHz APB1)
- Pass-all filter (mask=0x0000) on FIFO0
- Blocking send (`CAN_SendMsg` waits for TXOK)
- ISR pushes received messages to two FreeRTOS queues (`can_rx_queue`, `mqtt_can_rx_queue`)

**B. OTA CAN** (`Drivers/hardware/INT_CAN.c`, `INT_CAN.h`):
- Used by the OTA bootloader system
- Whitelist filter: only accepts StdID `0x0020` (mask `0xFFE0`)
- Non-blocking send
- 256-entry ring buffer in ISR (no FreeRTOS dependency)

### UART Drivers

| UART | File | Baud | RX Mode | Purpose |
|------|------|------|---------|---------|
| USART1 | `Core/Src/usart.c` | 115200 | Polling TX only | Debug printf (via `fputc` redirection) |
| USART2 | `Core/Src/usart.c` | 115200 | IRQ, 4-byte frame | Voice recognition module |
| USART3 | `Core/Src/usart.c` | 115200 | IRQ, 1-byte circular buffer | ESP8266 WiFi module |

### SPI Flash (W25Q128)

- **Location**: `Drivers/hardware/W25Q128.c`, `W25Q128.h`
- **Capacity**: 128Mbit (16MB)
- **Interface**: SPI2
- **API**: JEDEC ID read, status register polling, page program (256B), sector erase (4KB), block erase (64KB), chip erase
- **Used by**: OTA module to store incoming firmware images

### EEPROM (AT24C02)

- **Location**: `Drivers/hardware/AT24C02.c`, `AT24C02.h`
- **Capacity**: 256 bytes
- **Interface**: I2C1 (address `0xA0`/`0xA1`)
- **API**: Single-byte and multi-byte read/write with 16-byte page boundary handling
- **Used by**: OTA module stores update flag at `0x10` and check key `0x55A2` at `0x11`

## 6. Middleware Layer

### FreeRTOS

- **Version**: v10.3.1 (in `Middlewares/Third_Party/FreeRTOS/`)
- **API wrapper**: CMSIS-RTOS V2 (`CMSIS_RTOS_V2/`)
- **Config**: `Core/Inc/FreeRTOSConfig.h`
- **Heap**: 32KB, scheme 4 (`USE_FreeRTOS_HEAP_4`) — coalescing first-fit
- **Tick**: 1000Hz (1ms), driven by **TIM4** (not SysTick — SysTick is reserved for HAL)
- **Max priorities**: 56 (only 13-15 used)
- **Tick source**: `HAL_TIM_PeriodElapsedCallback` in `main.c` calls both `HAL_IncTick()` and `lv_tick_inc(1)`
- **Interrupt priorities**: 4-bit NVIC. FreeRTOS API-safe range: 5-15. All peripheral interrupts (CAN, USART2, USART3) are at priority 5.
- **Trace macros**: `traceTASK_SWITCHED_IN/OUT` defined in `FreeRTOSConfig.h` to enable LVGL CPU usage monitoring via `lv_freertos_task_switch_in/out()`

### LVGL

- **Version**: v9.5.0-dev (in `lvgl/`)
- **Config**: `lvgl/lv_conf.h`
- **Color**: 16-bit RGB565
- **OS**: FreeRTOS (`LV_USE_OS = LV_OS_FREERTOS`), task notifications enabled
- **Rendering**: Software only (`LV_USE_DRAW_SW = 1`), complex rendering **enabled** (`LV_DRAW_SW_COMPLEX = 1`)
- **Display**: Single partial buffer, 240x16 pixels (7.68KB), `LV_DISPLAY_RENDER_MODE_PARTIAL`
- **Refresh**: 33ms target (~30 FPS), `lv_timer_handler()` polled every 5ms in the LVGL task
- **Font**: Montserrat 14px only (`LV_FONT_MONTSERRAT_14 = 1`)
- **Layouts**: Flex and Grid both enabled
- **Themes**: Default, Simple, Mono all enabled
- **Debug**: Performance monitor (FPS/CPU) and memory monitor enabled on screen
- **Perf monitors**: `LV_USE_PERF_MONITOR = 1`, `LV_USE_MEM_MONITOR = 1`

**Enabled widgets** (23 of 37): animimg, arc, arclabel, bar, button, buttonmatrix, calendar, canvas, chart, checkbox, dropdown, image, imagebutton, label, led, line, list, menu, scale, switch, and more. See `lv_conf.h` for the complete list.

**Disabled widgets**: keyboard, lottie, msgbox, roller, slider, span, spinbox, spinner, table, tabview, textarea, tileview, win, 3dtexture.

> **Note**: `LV_USE_ST7789 = 1` is set but the actual display uses a custom FSMC porting layer, not the built-in ST7789 driver. This wastes code space.

### MQTT Client

- **Location**: `Middlewares/MQTTclient/`
- **Library**: jiejieTop/mqttclient (MQTT v3.1.1)
- **Config**: `mqttclient/mqtt_config.h`
  - Buffer size: 512 bytes
  - Command timeout: 5000ms
  - Keep-alive: 50 seconds
  - Max topic length: 64
- **Transport**: ESP8266 AT commands over USART3
- **Platform layer**: `platform/FreeRTOS/platform_esp8266_AT.c`
- **TLS**: mbedTLS source is included but may be disabled (`MQTT_NETWORK_TYPE_NO_TLS`)

### ESP8266 AT Command Layer

Three-layer architecture:

1. **HAL layer** (`HAL_AT/HAL_AT.c`): Raw byte send/receive over USART3, mutex-protected
2. **AT command layer** (`platform/FreeRTOS/platform_esp8266_AT.c`): `AT_send_cmd()`, `AT_send_data()`, response parsing
3. **AT parse task** (`freertos.c`, commented out): Parses `OK`/`ERROR`/`+IPD`/`>` responses from ESP8266

USART3 receives one byte at a time via interrupt, writes to a 512-byte circular buffer (`g_circle_buff`), and notifies the AT parse task via `vTaskNotifyGiveFromISR()`.

### OTA (Over-the-Air Update)

- **Location**: `Drivers/OTA/app_update.c`, `app_update.h`
- **Method**: CAN-based firmware transfer
- **State machine**:
  1. **IDLE** — normal operation
  2. **SEND** — triggered by UART1 command `"app_update"`, sends `"update"` over CAN (StdID 0)
  3. **RECEIVE** — streams firmware from CAN into W25Q128 in 256-byte pages, computes CRC32
  4. **CHECK** — receives CRC32 from host over CAN, verifies
  5. **WRITE** — writes header (app address `0x08010000` + size) to W25Q128, sets flags in AT24C02
  6. **JUMP** — sets MSP, relocates vector table, calls bootloader reset handler at `0x08000000`

## 7. Application Layer

### Boot Sequence

```
main()
  |-> __enable_irq()
  |-> HAL_Init()
  |-> SystemClock_Config()         // HSE 8MHz x PLL9 = 72MHz
  |-> MX_GPIO_Init()               // GPIO (LED, OLED I2C, etc.)
  |-> MX_CAN_Init()                // CAN1 500kbps
  |-> MX_USART3_UART_Init()       // ESP8266
  |-> MX_USART1_UART_Init()       // Debug printf
  |-> MX_USART2_UART_Init()       // Voice module
  |-> MX_FSMC_Init()               // LCD parallel interface
  |-> OLED_Init()                  // SSD1306
  |-> HAL_CAN_Start() + CAN_FilterConfig()
  |-> osKernelInitialize()
  |-> MX_FREERTOS_Init()           // Creates defaultTask
  |-> osKernelStart()              // Scheduler starts, never returns
```

`StartDefaultTask` (the bootstrap task) creates all application tasks and queues in a critical section, then self-deletes.

### FreeRTOS Tasks

| Task | Function | Stack | Priority | Status | Purpose |
|------|----------|-------|----------|--------|---------|
| `lvgl_demo` | `lvgl_demo_task()` | 1024 words (4KB) | 14 | Active | LCD init, LVGL init, calls `ui_init()`, runs `lv_timer_handler()` loop |
| `oled_task` | `oled_task()` | 200 words | 15 (highest) | Active | Reads CAN queue, updates OLED with vehicle status |
| `voice_task` | `voice_task()` | 128 words | 14 | Active | Reads voice queue, sends CAN commands |
| `can_task` | `can_task()` | 128 words | 13 (lowest) | Active | LED heartbeat (1s toggle). CAN TX code commented out |
| `AT_Parse` | `AT_Parse()` | 68 words | 15 | **Disabled** | ESP8266 AT response parser |
| `MQTT_Task` | `MQTT_Task()` | 200 words | 15 | **Disabled** | MQTT subscribe/publish over ESP8266 |

### Inter-Task Communication

**FreeRTOS Queues** (created in `StartDefaultTask`):

| Queue | Item Size | Depth | Producer | Consumer |
|-------|-----------|-------|----------|----------|
| `can_rx_queue` | `CanMsg_t` (11B) | 5 | CAN ISR | `oled_task` |
| `mqtt_can_rx_queue` | `CanMsg_t` (11B) | 5 | CAN ISR | `MQTT_Task` (disabled) |
| `voice_rx_queue` | `uint8_t` | 5 | USART2 ISR | `voice_task` |

### Data Flow

```
Voice Module (USART2)
  |-> HAL_UART_RxCpltCallback() validates 4-byte frame [0x4A, 0x5F, cmd, 0x8B]
  |-> xQueueSendFromISR(voice_rx_queue)
  |-> voice_task() -> CAN_SendMsg(0x77F or 0x7BF, {0xAA, 0x11, cmd})
       |
       v
CAN Bus <----------------------------------------------------+
  |                                                           |
  |-> HAL_CAN_RxFifo0MsgPendingCallback()                    |
  |   |-> xQueueSendFromISR(can_rx_queue)                    |
  |   |-> xQueueSendFromISR(mqtt_can_rx_queue)               |
  |                                                           |
  |   oled_task() decodes ID + data[2] -> updates OLED       |
  |   MQTT_Task() publishes to "mcu_test" topic [disabled]    |
  |                                                           |
MQTT Broker -> "MQTTSmart" topic -> MQTTSmart_handler() -----+
  (Chinese text commands -> CAN messages) [disabled]
```

### CAN Protocol

**Incoming status messages** (from other ECUs):

| StdID | Purpose | Data[2] encoding |
|-------|---------|-----------------|
| `0x666` | Lights/Windows/Sunroof | `0x01`=lights on, `0x02`=off, `0x03`=window open, `0x04`=close, `0x05`=sunroof open, `0x06`=close |
| `0x555` | Door | `0x07`=door open, `0x08`=door close |

**Outgoing command messages** (sent by voice/MQTT):

| StdID | Purpose | Payload |
|-------|---------|---------|
| `0x77F` | Lights/Windows/Sunroof commands | `{0xAA, 0x11, command_byte}` (command 0x01-0x06) |
| `0x7BF` | Door commands | `{0xAA, 0x11, command_byte}` (command 0x07-0x08) |

### Voice Module Protocol

4-byte fixed frame via USART2: `[0x4A] [0x5F] [command_byte] [0x8B]`

The ISR validates header/tail, extracts `command_byte`, and pushes to `voice_rx_queue`. The `voice_task` translates commands 0x01-0x08 into CAN messages.

### MQTT Topics

| Topic | Direction | Content | Status |
|-------|-----------|---------|--------|
| `MQTTSmart` | Subscribe | Chinese text commands (e.g., "打开车灯") | **Disabled** |
| `mcu_test` | Publish | Vehicle status updates | **Disabled** |

Broker: `10.60.14.76:1883` (no TLS in current config)

## 8. Development Guide

### Code Style

- 4-space indentation, C99 standard
- Chinese comments throughout the codebase
- CubeMX-generated code in `Core/Src/` and `Core/Inc/` — do not manually edit sections marked by CubeMX comment blocks
- User drivers in `Drivers/hardware/`
- Custom LVGL UI code in `lvgl/ui/ui.c` — all screen and widget creation goes here, called via `ui_init()` from `lvgl_demo_task`

### Common Pitfalls

1. **Stack overflow**: FreeRTOS tasks have small stacks (128-1024 words). Avoid large local arrays. Use `uxTaskGetStackHighWaterMark()` to check usage.
2. **LVGL thread safety**: `lv_timer_handler()` must be called from a single task only. Other tasks must not directly modify LVGL objects.
3. **CAN interrupt priority**: CAN RX IRQ priority is 5 (exactly at the FreeRTOS API-call boundary). Don't call FreeRTOS API from higher priority interrupts.
4. **FSMC timing**: LCD writes go through FSMC Bank 4. Ensure timing registers match the ILI9341 controller specs.
5. **Memory pressure**: FreeRTOS heap (32KB) + LVGL heap (12KB) + display buffer (7.68KB) + task stacks (~7.68KB) leaves <5KB free. Monitor `CAR.map` after any change.
6. **TIM4 as tick source**: FreeRTOS tick and LVGL tick both come from TIM4, not SysTick. Don't add SysTick-dependent code without understanding the impact.

### Known Issues

1. **ST7789 driver compiled but unused**: `LV_USE_ST7789 = 1` in `lv_conf.h` compiles the built-in ST7789 driver, but the actual display uses a custom FSMC porting layer. Set to 0 to save code space.
2. **Demos compiled in**: `LV_BUILD_DEMOS = 1` with widgets and benchmark demos enabled adds significant code size. Disable in production.
3. **CAN auto-retransmission disabled**: `HAL_CAN_Init` sets `AutoRetransmission = DISABLE`. This means failed transmissions are silently dropped.
4. **CAN filter is pass-all**: Filter mask is 0x0000, accepting all CAN IDs. This is fine for development but should be tightened for production.
5. **MQTT and AT_Parse tasks disabled**: Both are commented out in `freertos.c`. The `mqtt_can_rx_queue` is still created but unused.
