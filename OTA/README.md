# OTA 固件升级系统

基于 CAN 总线的车载 OTA（Over-The-Air）固件升级系统，支持can升级和本地串口备份升级。

---

## 系统概述

本系统为车载多节点控制器提供固件升级能力，包含三个独立的固件工程：

| 工程 | 目录 | 角色 | 目标芯片 |
|------|------|------|----------|
| **app_send_ZET6** | `app_send_ZET6/` | OTA 发送端（烧录器固件） | STM32F103ZET6 |
| **bootloader_start** | `bootloader_start/` | 目标板启动引导程序（正式版） | STM32F103ZET6 |
| **Backup programming** | `Backup programming/` | 目标板备份烧录程序（串口救砖） | STM32F103ZET6 |

## Flash 内存布局

STM32F103ZET6 具有 512KB 内部 Flash（`0x08000000 - 0x0807FFFF`）：

```
0x08000000 ┌───────────────────────────┐
           │  Bootloader (32KB)        │  bootloader_start 固件
           │  app_send_ZET6 也从此启动  │
0x08008000 ├───────────────────────────┤
           │  出厂默认应用 (16KB)       │  RESET_START
           │  Backup programming 固件  │  （备份烧录程序自身也存放于此）
           │  app_send_ZET6 存储接收的  │
           │  固件二进制文件            │
0x0800C000 ├───────────────────────────┤
           │  更新后的应用 (464KB)      │  APP_START
           │                           │
           │         ...               │
           │                           │
0x08080000 └───────────────────────────┘  APP_END_ADDR
```

### 外部存储

| 设备 | 接口 | 用途 |
|------|------|------|
| **W25Q32** (4MB SPI Flash) | SPI2 (PB12-CS, PB13-SCK, PB14-MISO, PB15-MOSI) | 固件暂存区：元数据（地址+大小）+ 固件二进制 |
| **W24C02** (256B EEPROM) | I2C1 (PB6-SCL, PB7-SDA) | 升级标志存储（地址 `0x10`） |

## 各工程详细说明

### 1. app_send_ZET6 — OTA 发送端

**作用**：运行在独立的烧录器板上，负责将 PC 串口收到的固件通过 CAN 总线发送给目标板。

**外设配置**：
- CAN1 (PA11-RX, PA12-TX)：1 Mbit/s
- USART1 (PA9-TX, PA10-RX)：接收 PC 固件
- CRC 硬件单元：固件校验

**工作流程**：

| 阶段 | 说明 |
|------|------|
| **接收固件** | PC 通过串口发送 `start:<长度>` 命令，然后发送二进制固件数据 |
| **存储固件** | 固件写入自身 Flash 的 `0x08008000` 地址 |
| **CAN 发送** | 目标板发送 `['s','g','g']` 命令请求更新，烧录器以 8 字节帧发送固件 |
| **CRC 校验** | 发送完成后计算硬件 CRC32，通过 CAN 发送校验值 |

**CAN 通信协议**：
- **请求帧**：目标板 → 烧录器，CAN ID `0`，数据 `['s', 'g', 'g']`
- **数据帧**：烧录器 → 目标板，CAN ID `1`，8 字节固件数据
- **校验帧**：烧录器 → 目标板，CAN ID `1`，4 字节 CRC32

---

### 2. bootloader_start — 启动引导程序

**作用**：目标板上电后首先运行，检查是否需要升级，执行固件拷贝，然后跳转到应用。

**外设配置**：
- USART1 (PA9-TX, PA10-RX)：115200 baud
- I2C1 (PB6-SCL, PB7-SDA)：W24C02 EEPROM
- SPI2 (PB12-CS, PB13-SCK, PB14-MISO, PB15-MOSI)：W25Q32 Flash
- GPIO：PE3-KEY1（中断），PE5-LED2，PB5-LED1

**启动流程**：

```
上电
 │
 ▼
① 读取升级标志 (W24C02 地址 0x10)
 │  - BOOT_UPDATE (0x01)：需要升级
 │  - BOOT_NO_UPDATE (0x02)：正常启动
 │  - BOOT_RESET (0x03)：恢复出厂
 │
 ▼
② 等待 3 秒（给用户按下 KEY1 恢复出厂的时间）
 │
 ▼
③ 执行升级（如果标志为 BOOT_UPDATE）
 │  - 从 W25Q32 读取元数据（起始地址 + 固件大小）
 │  - 验证固件合法性（栈指针、复位向量）
 │  - 擦除内部 Flash → 从 W25Q32 拷贝固件
 │  - 清除升级标志
 │
 ▼
④ 跳转到应用
    - BOOT_RESET → 跳转到 0x08008000（出厂默认）
    - 其他 → 跳转到 0x0800C000（更新后的应用）
```

**W25Q32 存储格式**：

| 地址 | 内容 | 大小 |
|------|------|------|
| `0x000000` | 固件起始地址（小端） | 4 字节 |
| `0x000004` | 固件大小（小端） | 4 字节 |
| `0x000008` | 固件二进制数据 | 可变 |

**W24C02 升级标志格式**（地址 `0x10`）：

| 偏移 | 内容 | 说明 |
|------|------|------|
| 0 | 状态字节 | `0x01`=升级, `0x02`=正常, `0x03`=恢复出厂 |
| 1-2 | 校验密钥 `0x5A6B` | 验证数据有效性 |

---

### 3. Backup programming — 备份烧录程序

**作用**：当 CAN 升级失败导致单片机无法正常运行时，通过串口直接下载固件，作为"救砖"手段。

**外设配置**：
- USART1 (PA9-TX, PA10-RX)：9600 baud
- GPIO：PE5-LED2，PB5-LED1

**特殊说明**：
- 本程序自身存放在 `0x08008000`，需要先通过 ST-Link 烧录
- 启动时手动重定位向量表：`SCB->VTOR = FLASH_BASE | 0x8000`

**使用方法**：

```
1. 通过 ST-Link 将 Backup programming 固件烧录到 0x08008000
2. 连接串口工具（9600 baud, 8N1）
3. 发送命令：start:<固件长度>
4. 发送二进制固件数据
5. 等待传输完成，程序自动跳转到 0x0800C000
```

**工作流程**：

```
上电启动 (0x08008000)
 │
 ▼
等待串口命令 "start:<长度>"
 │
 ▼
擦除 0x0800C000 起始的 10 个页 (20KB)
 │
 ▼
接收固件数据 → 写入 Flash
 │  - 1024 字节缓冲区
 │  - 半字 (16-bit) 写入
 │  - 2 秒超时判断传输结束
 │
 ▼
验证接收字节数 = 声明长度
 │  - 匹配 → 跳转到 0x0800C000
 │  - 不匹配 → 系统复位
```

## 三种组件对比

| 特性 | app_send_ZET6 | bootloader_start | Backup programming |
|------|---------------|------------------|-------------------|
| **角色** | 烧录器固件 | 目标板启动引导 | 目标板备份烧录 |
| **Flash 基址** | `0x08000000` | `0x08000000` | `0x08008000` |
| **应用地址** | `0x08008000` | `0x0800C000`（更新）/ `0x08008000`（出厂） | `0x0800C000` |
| **串口波特率** | — | 115200 | 9600 |
| **CAN 通信** | ✅ 1 Mbit/s | ❌ | ❌ |
| **外部 Flash** | ❌ | ✅ W25Q32 + W24C02 | ❌ |
| **固件来源** | PC 串口 → CAN | W25Q32 外部 Flash | PC 串口直连 |
| **校验方式** | 硬件 CRC32 | 依赖外部 Flash 完整性 | 字节计数验证 |
| **输出格式** | `.hex` | `.bin` | `.bin` |

## 开发环境

- **IDE**：Keil MDK-ARM V5 (uVision 5)
- **编译器**：ARMCC V5.06
- **调试器**：ST-Link V2
- **串口工具**：任意串口助手（推荐 SSCOM 或 PuTTY）

每个子工程都是独立的 Keil 项目：

```bash
# 打开对应工程文件

bootloader_start/MDK-ARM/2.uvprojx                # 启动引导程序

```

构建后在 `MDK-ARM/` 目录下生成 `.hex` 或 `.bin` 文件。

## 完整升级操作步骤

### 正常 OTA 升级（CAN 总线）

```
1. 编译目标板应用，生成 .bin 文件
2. 将 .bin 文件通过串口发送给 app_send_ZET6 烧录器
3. 在目标板主程序中触发 OTA 更新（发送 "update" 到 USART1）
4. 目标板自动：接收 CAN 数据 → 写入 W25Q32 → 设置升级标志 → 复位
5. bootloader_start 自动：读取标志 → 拷贝固件 → 跳转新应用
```

### 备份串口升级（救砖）

```
1. 用 ST-Link 将 Backup programming 烧录到 0x08008000
2. 连接串口（9600 baud）
3. 发送 "start:<固件字节数>"
4. 发送固件二进制数据
5. 等待自动跳转到新应用
```

## 注意事项

1. **CAN 过滤器配置**：目标板需配置 FilterBank 隔离应用数据（FIFO0）和 OTA 数据（FIFO1），避免过滤器冲突导致 OTA 数据丢失
2. **Flash 写入对齐**：STM32 Flash 写入必须半字（16-bit）对齐，代码中已处理奇数字节情况
3. **W25Q32 忙等待**：SPI Flash 擦除/写入时需等待 busy 位清除，建议添加超时保护（5 秒）
4. **备份烧录前置条件**：使用 Backup programming 前，必须先通过 ST-Link 烧录该程序到 `0x08008000`
5. **固件大小限制**：更新应用最大 464KB（`0x0800C000 - 0x0807FFFF`）
